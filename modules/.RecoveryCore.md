Lightweight recovery agent core that establishes a minimal MeshAgent session with terminal access, file transfer, and tunnel management capabilities for disaster recovery scenarios.

## Key Components

| Export/Function | Description |
|---|---|
| `meshCoreObj` | Agent identity object declaring recovery mode with capability bitmask (14 = Terminal + Files + Console) |
| `sendConsoleText(msg)` | Sends console output messages back to the MeshAgent server |
| `getServerTargetUrl(path)` | Constructs a full server URL from the active agent connection |
| `getServerTargetUrlEx(url)` | Resolves relative (`*/path`) or absolute tunnel URLs |
| `onTunnelUpgrade(response, s, head)` | Handles WebSocket upgrade for new tunnels; routes to TCP relay or KVM/Terminal/Files mode |
| `splitArgs(str)` / `parseArgs(argv)` | CLI-style argument parsing with quoted string support |
| `objToString(x, ...)` | Recursive object serializer for debug output |
| `path.join(...)` | Minimal cross-platform path joining utility |

## Usage Example

```javascript
// The recovery core self-initializes on agent connection
require('MeshAgent').on('Connected', function () {
    require('os').name().then(function (v) {
        sendConsoleText("Mesh Agent Recovery Console, OS: " + v);
        require('MeshAgent').SendCommand(meshCoreObj);
    });
});

// Tunnel commands are dispatched automatically via AddCommandHandler
// Protocol '1' inside a tunnel opens a remote terminal:
// - Windows: uses win-terminal native pipe
// - Linux/macOS: spawns /bin/sh with TERM type via childProcess
```

## Notes

- Capability bitmask `14` = Terminal (2) + Files (4) + Console (8); Desktop (1) and JavaScript (16) are excluded in recovery mode.
- File uploads/downloads are tracked per tunnel via `uploadFile`/`downloadFile` handles and cleaned up on tunnel close.
- TCP relay tunnels pause the socket until the local target connection is established.

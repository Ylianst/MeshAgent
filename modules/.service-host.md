Cross-platform Windows service host abstraction that manages service lifecycle (install, uninstall, start, stop) and dispatches service control events using native Win32 APIs via `_GenericMarshal`, with fallback support for Linux systemd/init environments.

## Key Components

### `serviceHost(serviceName)` constructor
Creates a service host instance that wraps Windows Service Control Manager (SCM) integration and emits lifecycle events.

**Emitted Events:**
| Event | Description |
|---|---|
| `serviceStart` | Fired when the service successfully starts |
| `serviceStop` | Fired on `SERVICE_CONTROL_STOP` or `SIGTERM` (Linux) |
| `normalStart` | Fired when the process is launched outside of SCM context |
| `session` | Windows session change events (logon/logoff/lock) |
| `powerStateChange` | Windows power state change events |

### `run()` method
Processes CLI arguments and starts the service dispatcher. Supports the following arguments:

| Argument | Action |
|---|---|
| `-install` | Installs the service via `service-manager` |
| `-uninstall` | Removes the service |
| `start` / `-d` | Starts the service (Win32 only) |
| `stop` / `-s` | Stops the service (Win32 only) |

### Platform Constants
`SERVICE_WIN32`, `SERVICE_STATE`, `SERVICE_ACCEPT`, `SERVICE_CONTROL`, `SESSION_CHANGE_TYPE` — Win32 SCM flag enumerations used for native interop.

## Usage Example

```javascript
const serviceHost = require('./service-host');

const svc = new serviceHost({
  name: 'MyAgentService',
  servicePath: process.execPath
});

svc.on('serviceStart', () => {
  console.log('Service started, initializing agent...');
  // Begin main service logic
});

svc.on('serviceStop', () => {
  console.log('Service stopping, cleaning up...');
  process.exit(0);
});

svc.on('normalStart', () => {
  console.log('Running in interactive/debug mode');
});

svc.run();
// CLI: node agent.js -install
// CLI: node agent.js -uninstall
```

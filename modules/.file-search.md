Cross-platform file search utility that locates files matching name patterns by spawning native OS processes — PowerShell (`Get-ChildItem`) on Windows and `/usr/bin/find` on Linux/macOS.

## Key Components

- **`filesearch` (class)** — Singleton constructor that selects the platform-appropriate `find` implementation at load time.
- **`find(root, criteria)`** — Searches `root` recursively for files matching `criteria` (a string glob or array of globs). Returns a Promise augmented with `result` and `end` EventEmitter events.
- **`cancel()`** — Method on the returned promise object that kills the underlying child process.

## Usage Example

```javascript
const fileSearch = require('./file-search');

const search = fileSearch.find('C:\\Users\\admin', ['*.log', '*.txt']);

search.on('result', (filePath) => {
  console.log('Found:', filePath);
});

search.on('end', () => {
  console.log('Search complete');
});

// Optionally cancel mid-search
setTimeout(() => search.cancel(), 5000);
```

## Platform Behavior

| Platform | Backend | IPC Method |
|---|---|---|
| `win32` | PowerShell `Get-ChildItem` | Named pipe (`\\.\pipe\mesh-<uuid>`) |
| Linux / macOS | `/usr/bin/find` | stdout streaming |

## Notes

- The returned object is both a **Promise** and an **EventEmitter** — `await` it for completion or listen to `result` for streaming results.
- On Windows, results are streamed back over a named pipe to avoid PowerShell stdout buffering issues.
- The module exports a **singleton instance**, so `require('./file-search')` always returns the same object.

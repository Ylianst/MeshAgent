Bundles a JavaScript source file and optional module dependencies into a self-contained executable by appending them to a binary (e.g., `MeshAgent.exe`), using a magic GUID marker to detect and replace any previously embedded JavaScript.

## Key Components

- **CLI argument parsing** — Handles `-o` (output), `-x` (input binary), `-d` (dependencies folder), `-i` (individual dependency files), and a positional `.js`/`.zip` source argument
- **`exeJavaScriptGuid`** — Magic hex string (`B996015880544A19B7F7E9BE44914C18`) appended as a 16-byte trailer to identify embedded JavaScript payloads
- **Dependency merging** — Reads `-i` files or all files in a `-d` folder, encodes them as `addModule(...)` calls prepended to the source JS
- **PE signature check** — Uses `PE_Parser` to abort if the target binary is code-signed
- **`OnWroteExe()`** — Async write handler that quad-word-aligns the JS payload, writes it after the binary, then appends a 4-byte length and the magic GUID
- **`escapeCodeString(str)`** — Escapes special characters (quotes, backslashes, control chars) so dependency source strings can be safely embedded as JavaScript string literals

## Usage Example

```bash
# Basic: embed meshcmd.js into MeshService64.exe → meshcmd.exe
MeshAgent.exe -omeshcmd.exe -xMeshService64.exe meshcmd.js

# With individual dependency modules
MeshAgent.exe -omeshcmd.exe -imodule1.js -imodule2.js -xMeshService64.exe meshcmd.js

# With a folder of dependencies
MeshAgent.exe -omeshcmd.exe -d./modules -xMeshService64.exe meshcmd.js
```

```javascript
// The tool prepends dependency modules as addModule() calls before the source JS:
addModule('module1', "...escaped source...");
addModule('module2', "...escaped source...");
// <original meshcmd.js content follows>
```

> **Note:** The target executable must be **unsigned**. Signed binaries are rejected to prevent breaking code-signing integrity.

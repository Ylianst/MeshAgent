Brief header providing symbol name remapping macros to resolve case-insensitive linker conflicts on OpenVMS (VMS) systems, where symbol name collisions can occur due to the OS treating uppercase and lowercase identifiers as equivalent.

## Key Components

**VMS-Specific Symbol Remaps** (active only when `OPENSSL_SYS_VMS` is defined):

| Original Symbol | Remapped Symbol |
|---|---|
| `ERR_load_CRYPTO_strings` | `ERR_load_CRYPTOlib_strings` |
| `OCSP_crlID_new` | `OCSP_crlID2_new` |
| `d2i_ECPARAMETERS` | `d2i_UC_ECPARAMETERS` |
| `i2d_ECPARAMETERS` | `i2d_UC_ECPARAMETERS` |
| `d2i_ECPKPARAMETERS` | `d2i_UC_ECPKPARAMETERS` |
| `i2d_ECPKPARAMETERS` | `i2d_UC_ECPKPARAMETERS` |

**Compatibility Alias:**
- `HEADER_SYMHACKS_H` — legacy guard defined when `OPENSSL_NO_DEPRECATED_3_0` is not set, preserving backward compatibility with older code that checks for this macro.

## Usage Example

This header is typically included indirectly via other OpenSSL headers. On non-VMS platforms, it compiles to a no-op. On VMS, the remapping is transparent to callers:

```c
#include <openssl/symhacks.h>

/* On VMS, this call is silently redirected to ERR_load_CRYPTOlib_strings()
   to avoid a case-insensitive linker collision with CRYPTO_strings */
ERR_load_CRYPTO_strings();

/* Similarly, EC parameter encode/decode functions are remapped
   to avoid collisions between ECPARAMETERS and ECPKPARAMETERS */
d2i_ECPARAMETERS(NULL, &buf, len);
```

No action is needed by the developer — the `#define` macros handle the renaming at the preprocessor stage before compilation.

Compatibility shim header that preserves deprecated SSL function-code (`SSL_F_*`) macros and the `ERR_load_SSL_strings` declaration from OpenSSL 1.1.1 for codebases not yet migrated to OpenSSL 3.0's error-reporting model.

## Key Components

- **`ERR_load_SSL_strings(void)`** — Deprecated function declaration (guarded by `OSSL_DEPRECATEDIN_3_0`) that previously registered SSL error strings into the OpenSSL error subsystem. No-op in OpenSSL 3.0+.
- **`SSL_F_*` macros** — ~200+ function-code constants, all defined to `0`. In OpenSSL 1.1.1 these carried numeric identifiers used in error reporting; in 3.0 they are zeroed out for backward-source-compatibility only.
- **Guard macro** `OPENSSL_NO_DEPRECATED_3_0` — All symbols are conditionally compiled; suppressing deprecated APIs removes this entire block.

## Usage Example

This header is **not intended for direct inclusion**. It is automatically pulled in by `<openssl/sslerr.h>`:

```c
/* DO NOT do this: */
#include <openssl/sslerr_legacy.h>   /* wrong */

/* DO this instead: */
#include <openssl/sslerr.h>          /* correct — includes legacy symbols automatically */
```

If your code references `SSL_F_*` macros for legacy error-handling patterns, they will compile cleanly against OpenSSL 3.0 but resolve to `0`:

```c
/* Legacy 1.1.1-style error — still compiles on 3.0, macro evaluates to 0 */
SSLerr(SSL_F_SSL_CTX_NEW, SSL_R_NULL_SSL_CTX);
```

> **Migration note:** These symbols will be removed in a future OpenSSL release. Migrate error reporting to the `ERR_raise()` / `OSSL_ERR_*` APIs introduced in OpenSSL 3.0.

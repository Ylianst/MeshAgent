Compatibility header that preserves deprecated pre-3.0 OpenSSL error-loading function symbols and legacy `_F_` function code macros, allowing older code to compile against OpenSSL 3.0+ without source changes.

## Key Components

### Deprecated `ERR_load_*` Functions
All declared with `OSSL_DEPRECATEDIN_3_0`, these no-op stubs replace the pre-3.0 pattern of manually registering error strings per subsystem. Covered subsystems include:

- Core: `CRYPTO`, `ERR`, `EVP`, `BN`, `BUF`, `BIO`, `ASN1`, `CONF`, `OBJ`, `PEM`, `RAND`
- Asymmetric: `RSA`, `DSA`, `DH`, `EC`
- Higher-level: `PKCS7`, `PKCS12`, `CMS`, `OCSP`, `X509`, `X509V3`, `KDF`, `TS`, `UI`, `ASYNC`, `OSSL_STORE`

Optional subsystems are conditionally compiled via feature guards (e.g., `OPENSSL_NO_CMS`, `OPENSSL_NO_EC`).

### Legacy `_F_` Macro Definitions
Hundreds of `ASN1_F_*`, `ASYNC_F_*`, and `BIO_F_*` macros (and more in the full file) are defined as `0`. In OpenSSL 3.0, function codes were removed from the error system; these stubs allow legacy code referencing them to compile without modification.

## Usage Example

This header is **not meant for direct inclusion**. It is pulled in automatically by the public `cryptoerr.h` header:

```c
/* Do NOT do this: */
#include <openssl/cryptoerr_legacy.h>

/* Instead, include the standard public header: */
#include <openssl/err.h>

/* Legacy call sites compile but are no-ops in OpenSSL 3.0+ */
ERR_load_RSA_strings();  /* deprecated, does nothing */

/* Legacy macro usage compiles cleanly */
if (ERR_GET_FUNC(err) == RSA_F_RSA_SIGN) { /* RSA_F_RSA_SIGN == 0 */ }
```

> **Note:** Guard with `OPENSSL_NO_DEPRECATED_3_0` to suppress deprecation warnings, or migrate to the OpenSSL 3.0 error API which auto-loads error strings.

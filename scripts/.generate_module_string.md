Embeds a compiled JavaScript module into the MeshAgent C source file (`ILibDuktape_Polyfills.c`) by compressing it with deflate, encoding it as Base64, and injecting the result into an auto-generated section of the C file.

## Key Components

### `embedModule(moduleName)`

The main function that handles the full embed pipeline:

- **File validation** — verifies `modules_expanded/<moduleName>.js` and `microscript/ILibDuktape_Polyfills.c` exist
- **Compression** — reads the module source and applies `zlib.deflateSync` to produce a deflate-compressed Base64 payload
- **Code generation** — selects one of two C code strategies based on payload size:
  - **Small modules** (`< 8000` chars): single `duk_peval_string_noresult` call with inline `addCompressedModule`
  - **Large modules** (`≥ 8000` chars): `ILibMemory_Allocate` + chunked `memcpy_s` calls + `ILibDuktape_AddCompressedModuleEx`
- **Injection** — locates `// {{ BEGIN AUTO-GENERATED BODY` / `// }} END OF AUTO-GENERATED BODY` markers in the C file and either replaces an existing module entry or appends a new one

## Usage Example

```bash
# Embed a specific module
node generate_module_string.js my-module

# Defaults to 'win-terminal' if no argument provided
node generate_module_string.js
```

```bash
# After embedding, recompile the agent
make macos ARCHID=29
```

## Notes

- Expects module source files under `modules_expanded/` relative to the working directory
- The C target file must contain both `BEGIN AUTO-GENERATED BODY` and `END OF AUTO-GENERATED BODY` marker comments or the script will exit with an error
- Module names with hyphens (e.g. `win-terminal`) are sanitized (hyphens stripped) when used as C variable names
- Source: [`generate_module_string.js`](https://github.com/flamingo-stack/meshagent/blob/main/generate_module_string.js)

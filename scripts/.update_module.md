A Node.js CLI utility that reads a JavaScript module, compresses it with zlib deflate, encodes it as Base64, and injects the result into the MeshAgent C source file (`ILibDuktape_Polyfills.c`) for embedding as a Duktape polyfill module.

## Key Components

### `updateModule(moduleName)`

Core function that orchestrates the full read → compress → encode → inject pipeline. Supports two target modules with distinct embedding formats:

| Module | Embedding Format |
|---|---|
| `service-manager` | `ILibMemory_Allocate` + chunked `memcpy_s` blocks |
| `agent-installer` | Inline `duk_peval_string_noresult` or chunked `memcpy_s` (auto-detected) |

**Internal steps:**
1. Reads `modules/<moduleName>.js`
2. Compresses with `zlib.deflateSync`
3. Encodes to Base64 (chunked at 16,000 bytes for large modules)
4. Derives a timestamp from the source file's `mtime`
5. Locates the existing block in the C file via regex and replaces it in-place

## Usage Example

```bash
# Embed the service-manager module into the C polyfills file
node update_module.js service-manager

# Embed the agent-installer module
node update_module.js agent-installer
```

```bash
# Expected console output
Updating module: service-manager
- Module size: 42310 bytes
- Compressed size: 14872 bytes
- Base64 size: 19832 bytes
Module service-manager updated successfully!
```

## Notes

- **Input:** `modules/<moduleName>.js`
- **Output (modified in-place):** `microscript/ILibDuktape_Polyfills.c`
- The 16,000-byte chunk size for `memcpy_s` avoids MSVC string literal length limits
- Timestamps are derived from source file `mtime` and embedded into the C registration call to enable module versioning at runtime
- Adding support for new modules requires extending the conditional branching in `updateModule`

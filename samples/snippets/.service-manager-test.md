A test/demonstration script that walks through the core features of the `service-manager` module, showing how to retrieve and inspect a running system service by name.

## Key Components

| Component | Description |
|---|---|
| `service-manager` module | Native MeshAgent module for interacting with OS service managers (Windows SCM, Linux systemd/init) |
| `manager.getService(name)` | Singleton manager method that returns a service object or throws if not found |
| `serviceInstance.appLocation()` | Returns the filesystem path to the service binary |
| `serviceInstance.appWorkingDirectory()` | Returns the working directory configured for the service |
| `serviceInstance.startType` | Property indicating start behavior (`AUTO_START`, `DEMAND_START`, etc.) |
| `serviceInstance.isRunning()` | Returns whether the service is currently active |

## Usage Example

Run this snippet directly via the MeshAgent runtime, passing a service name as the argument:

```bash
# Windows
MeshService64 ..\snippets\service-manager-test.js "Mesh Agent"

# Linux
./meshagent_x86_64 snippets/service-manager-test.js meshagent
```

The core lookup and inspection pattern used in the script:

```javascript
const manager = require('service-manager').manager;

try {
    const svc = manager.getService('meshagent');

    console.log('Binary path:    ', svc.appLocation());
    console.log('Working dir:    ', svc.appWorkingDirectory());
    console.log('Start type:     ', svc.startType);
    console.log('Running:        ', svc.isRunning());
} catch (e) {
    console.log('Service not found:', e.message);
    process.exit(1);
}
```

> **Note:** `getService()` throws an exception if the service name is not registered with the platform's service manager. Always wrap calls in a `try/catch`.

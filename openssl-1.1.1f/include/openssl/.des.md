OpenSSL DES (Data Encryption Standard) cryptographic API header, providing type definitions, constants, and function declarations for single, double, and triple DES encryption operations.

## Key Components

### Types
- **`DES_cblock`** — 8-byte DES block (`unsigned char[8]`)
- **`const_DES_cblock`** — const-safe variant of `DES_cblock`
- **`DES_key_schedule`** — 16-round expanded key schedule structure
- **`DES_LONG`** — `unsigned int` platform word type

### Constants & Macros
| Macro | Value | Purpose |
|---|---|---|
| `DES_ENCRYPT` | `1` | Encrypt direction flag |
| `DES_DECRYPT` | `0` | Decrypt direction flag |
| `DES_KEY_SZ` | `sizeof(DES_cblock)` | Key size (8 bytes) |
| `DES_ecb2_encrypt` | — | 2-key ECB (wraps 3-key with k1 reuse) |
| `DES_ede2_*` | — | 2-key EDE wrappers for 3-key EDE variants |

### Key Functions
- **`DES_set_key_checked`** / **`DES_set_key_unchecked`** — expand raw key into schedule
- **`DES_ecb_encrypt`** / **`DES_ecb3_encrypt`** — ECB mode (single/triple DES)
- **`DES_ncbc_encrypt`** / **`DES_ede3_cbc_encrypt`** — CBC mode with IV update
- **`DES_cfb64_encrypt`** / **`DES_ofb64_encrypt`** — CFB-64 / OFB-64 streaming modes
- **`DES_encrypt1`** / **`DES_encrypt2`** / **`DES_encrypt3`** — low-level core primitives
- **`DES_is_weak_key`** / **`DES_set_odd_parity`** — key validation utilities
- **`DES_crypt`** / **`DES_fcrypt`** — Unix crypt(3) compatible password hashing

## Usage Example

```c
#include <openssl/des.h>

DES_cblock      key_block = { 0x01,0x23,0x45,0x67,0x89,0xAB,0xCD,0xEF };
DES_key_schedule ks;
DES_cblock      ivec     = { 0 };

/* Set odd parity, check for weak keys, expand schedule */
DES_set_odd_parity(&key_block);
if (DES_is_weak_key(&key_block)) { /* handle error */ }
DES_set_key_checked(&key_block, &ks);

unsigned char plaintext[8]  = "Hello!!!";
unsigned char ciphertext[8] = { 0 };

/* Single-DES CBC encrypt (use DES_ncbc_encrypt to update IV) */
DES_ncbc_encrypt(plaintext, ciphertext, 8, &ks, &ivec, DES_ENCRYPT);
```

> **⚠️ Security Note:** DES uses a 56-bit effective key and is considered cryptographically broken. Prefer AES (`<openssl/aes.h>`) for new implementations.

Provides symbol name remapping macros to resolve case-insensitive linker conflicts on OpenVMS systems, where symbol names differing only in case are treated as identical.

## Key Components

| Macro Redefinition | Original Symbol | VMS-Safe Replacement |
|---|---|---|
| `ERR_load_CRYPTO_strings` | `ERR_load_CRYPTO_strings` | `ERR_load_CRYPTOlib_strings` |
| `OCSP_crlID_new` | `OCSP_crlID_new` | `OCSP_crlID2_new` |
| `d2i_ECPARAMETERS` | `d2i_ECPARAMETERS` | `d2i_UC_ECPARAMETERS` |
| `i2d_ECPARAMETERS` | `i2d_ECPARAMETERS` | `i2d_UC_ECPARAMETERS` |
| `d2i_ECPKPARAMETERS` | `d2i_ECPKPARAMETERS` | `d2i_UC_ECPKPARAMETERS` |
| `i2d_ECPKPARAMETERS` | `i2d_ECPKPARAMETERS` | `i2d_UC_ECPKPARAMETERS` |
| `cms_Data_create` | `cms_Data_create` | `priv_cms_Data_create` |

All remappings are **conditionally compiled** under `OPENSSL_SYS_VMS` only, making this header a no-op on all other platforms.

## Usage Example

This header is typically included transitively via OpenSSL internals. On VMS builds, including it transparently redirects conflicting symbol calls:

```c
#include <openssl/symhacks.h>

/* On VMS, this call is transparently redirected to
 * ERR_load_CRYPTOlib_strings() at compile time */
ERR_load_CRYPTO_strings();

/* On all other platforms, the macro is not defined
 * and the original symbol name is used unchanged */
```

> **Note:** The `cms_Data_create` → `priv_cms_Data_create` remap specifically resolves a collision with the public `CMS_data_create` symbol — a case-folding clash unique to VMS linker behavior.

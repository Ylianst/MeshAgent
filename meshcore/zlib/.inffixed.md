Auto-generated lookup tables used internally by zlib's inflate (decompression) engine to decode fixed Huffman codes as defined by the DEFLATE specification (RFC 1951).

## Key Components

### `lenfix[512]` — Literal/Length Decode Table
A 512-entry static lookup table of `code` structs for decoding fixed literal/length Huffman codes. Each entry encodes three fields:

```text
{op, bits, val}
 ↑    ↑     ↑
 |    |     └─ decoded value (literal byte, length, or distance)
 |    └─────── number of bits consumed from the bitstream
 └──────────── operation flags (copy, end-of-block, error, etc.)
```

Notable `op` values:
- `0` — literal or length symbol
- `16`–`21` — length with extra bits
- `64` — invalid/error entry
- `96` — end-of-block

### `distfix[32]` — Distance Decode Table
A 32-entry static lookup table of `code` structs for decoding fixed distance codes. Entries follow the same `{op, bits, val}` format, where `val` is the base distance and `op` encodes the number of extra bits needed.

## Usage Example

Both tables are consumed internally by `inflate_fast()` and the main inflate loop in `inflate.c`:

```c
/* Internal inflate usage — not for application code */
#include "inffixed.h"

/* Decode a literal/length symbol using a 9-bit index */
code entry = lenfix[hold & 0x1FF];   /* hold = current bit buffer */
unsigned op   = entry.op;
unsigned bits = entry.bits;
unsigned val  = entry.val;

/* Decode a distance symbol using a 5-bit index */
code dist_entry = distfix[hold & 0x1F];
```

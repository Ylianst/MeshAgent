Header defining macOS application bundle detection utilities for the MeshAgent binary, enabling it to distinguish between bundle and standalone execution environments and adjust its working directory accordingly.

## Key Components

| Function | Description |
|---|---|
| `is_running_from_bundle()` | Returns `1` if the process is running inside a `.app` bundle, `0` if standalone |
| `get_bundle_path()` | Returns a heap-allocated string with the full `.app` directory path; caller must `free()` |
| `adjust_working_directory_for_bundle()` | Changes the working directory to the bundle's parent on bundle execution; no-op for standalone binaries |

> **Platform guard:** All declarations are conditionally compiled under `#ifdef __APPLE__`, so this header is a no-op on non-Apple platforms.

## Usage Example

```c
#include "bundle_detection.h"

int main(void) {
#ifdef __APPLE__
    /* Call early, before any relative-path file I/O */
    if (adjust_working_directory_for_bundle() != 0) {
        fprintf(stderr, "Failed to set working directory\n");
        return 1;
    }

    if (is_running_from_bundle()) {
        char *path = get_bundle_path();
        if (path) {
            printf("Bundle root: %s\n", path);
            free(path); /* Caller is responsible for freeing */
        }
    }
#endif
    /* Continue with normal startup... */
    return 0;
}
```

**Notes:**
- Call `adjust_working_directory_for_bundle()` as early as possible in `main()` before any file I/O that relies on relative paths.
- Always `free()` the pointer returned by `get_bundle_path()` to avoid memory leaks.
- The implementation uses CoreFoundation to reliably detect bundle execution, correctly ignoring standalone binaries that carry an embedded `Info.plist`.

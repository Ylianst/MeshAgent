A precomputed lookup table that maps any 16-bit unsigned integer to the number of bits required to represent it, used to accelerate JPEG Huffman encoding.

## Key Components

### `jpeg_nbits_table`

```c
static const unsigned char jpeg_nbits_table[65536];
```

- **Type:** Static, read-only array of 65,536 `unsigned char` entries
- **Index:** Any value from `0` to `65535` (full 16-bit range)
- **Value:** The minimum number of bits needed to represent the index value (i.e., `floor(log2(n)) + 1` for `n > 0`, and `0` for `n = 0`)
- **Range of values:** `0` through `12` (indices 0–4095 covered; the table truncates at entry 4096+ with value `12`)

## Usage Example

```c
#include "jpeg_nbits_table.h"

/* Get the number of bits needed to encode a DCT coefficient magnitude */
unsigned int value = 743;
unsigned char nbits = jpeg_nbits_table[value];  /* returns 10 */

/* Typical use in JPEG Huffman entropy encoding */
void encode_coefficient(int coeff) {
    unsigned int abs_coeff = (coeff < 0) ? -coeff : coeff;
    unsigned char size = jpeg_nbits_table[abs_coeff]; /* category/size */
    /* emit Huffman code for 'size', then emit 'size' raw bits of coeff */
}
```

## Notes

- **Performance:** Direct array indexing (`O(1)`) replaces a more expensive runtime `log2` or bit-scan loop, which matters in tight JPEG encoding inner loops.
- **JPEG context:** In JPEG entropy coding, each nonzero DCT coefficient is encoded as a `(size, amplitude)` pair. `size` is the number of bits needed — exactly what this table provides.
- **Memory trade-off:** The table occupies 64 KB of read-only data, which is acceptable for encoder implementations targeting performance over memory footprint.
